Funny позволяет пользователю описывать модули. Модуль состоит из именованных функций и формул.

Предыстория и обоснование Funny
Цели языка:

Простота синтаксического разбора.
Простота компиляции в выбранное низкоуровневое представление.
Достаточная сложность, чтобы демонстрировать верификацию императивных программ.
Отсюда: несколько возвращаемых значений, неизменяемые параметры, явные области видимости, формулы в дополнение к функциям.

Основы языка
Пробелы/табуляции/переводы строк эквивалентны одному пробелу. Комментарии // ... до конца строки считаются пробелами.

Типы и константы
int — математические целые (в логике) и 32-битные знаковые при исполнении (переполнение по модулю 2^32).
int[] — массив целых; длина неизменяема во время выполнения, length(a) возвращает длину.
Логические константы true/false и булевы операции используются в условиях и предикатах; отдельного типа bool для переменных нет.
Идентификаторы
Идентификаторы начинаются с латинской буквы и содержат буквы/цифры. Присваивание массивов имеет семантику копирования: b = a; создает копию массива.

Исключения
Деление на ноль.
Доступ к массиву вне границ.
Обработки внутри языка нет; перехват возможен во внешнем коде.

Функции и типы
Все функции экспортируются. Синтаксис:

function = identifier
    "(" [ variableDef {"," variableDef } ] ")"
    ["requires" predicate ]
    "returns" variableDef {"," variableDef }
    ["ensures" predicate ]
    [ "uses" localVarDef {"," localVarDef } ]
    statement;

variableDef =
    identifier ":" variableType;

localVarDef =
    identifier [ ":" variableType ];

variableType = "int" | "int[]";
Параметры/возвраты требуют явного типа.
Локальные переменные могут опускать тип; компилятор выводит его из первого корректного присваивания (см. ниже).
Имена параметров, возвратов и локальных переменных уникальны в пределах функции.
Функции можно вызывать рекурсивно; имена уникальны в модуле.
Пред- и постусловия
requires использует параметры; по умолчанию true.
ensures использует параметры и возвращаемые значения; по умолчанию false (для задания явных требований).
Определения формул
Формулы используются только в предикатах:

formula = identifier "(" [ variableDef {"," variableDef  } ] ")" "=>" predicate;
Операторы
Типы операторов:

statement = assignment | conditional | loop | block | assertStmt | assumeStmt;
Оператор присваивания
assignment =
    varName "=" expr ";"
  | arrayAccess "=" expr ";"                     (* синтаксический сахар для функционального обновления массива *)
  | varName { "," varName } "=" functionCall ";"
Параметры функции (включая массивы) доступны только для чтения и не могут быть в левой части присваивания. Локальные переменные и возвращаемые значения доступны для чтения/записи; чтение неинициализированного — неопределено.

Обновление массива: синтаксический сахар
a[i] = v; обессахаривается в функциональное обновление с копированием:

a[i] = v;      // эквивалентно a = set(a, i, v);
a[i][j] = v;   // эквивалентно: tmp = a[i]; tmp = set(tmp, j, v); a = set(a, i, tmp);
Функция set — часть семантического описания, не публичного API.

Условный оператор
conditional = "if" "(" condition ")" statement ["else" statement];
Оператор цикла
while = "while" "(" condition ")"
    [ "invariant" predicate ]
    statement;
Если инвариант опущен, считается true.

Блочный оператор
block = "{" { statement } "}";
Точка с запятой — часть присваивания, не разделитель.

Операторы assert и assume
assertStmt = "assert" predicate ";"
assumeStmt = "assume" predicate ";"
assert проверяется при верификации (и опционально в рантайме); нарушение — ошибка. assume сужает пространство состояний для верификации; в рантайме может игнорироваться или проверяться по флагу.

Выражения
expr =
    functionCall
  | arrayAccess
  | number
  | variable
  | "-" expr
  | expr "+" expr
  | expr "*" expr
  | expr "-" expr
  | expr "/" expr
  | "(" expr ")";
Вызов функции
functionCall = identifier "(" [ expr {"," expr} ] ")";
Функции с множественным возвратом недопустимы внутри выражений — только в присваивании кортежа. Аргументы вычисляются слева направо. Типы/количество аргументов должны совпадать с объявлением. Встроенная функция length(a: int[]) returns l: int.

Обращение к элементу массива
arrayAccess = varName "[" expr "]"
Переменная должна иметь тип int[], индекс — int. Выход за границы — исключение. Обновление через a[i] = v — функциональное копирование (см. выше).

Условия
condition =
    "true" | "false"
  | comparison
  | "not" condition
  | condition "and" condition
  | condition "or" condition
  | condition "->" condition
  | "(" condition ")";

comparison =
    expr "==" expr | expr "!=" expr
  | expr ">=" expr | expr "<=" expr
  | expr ">" expr  | expr "<" expr;
Приоритет: not > and > or > →. Импликация правоассоциативна.

Предикаты
predicate =
    quantifier
  | formulaRef
  | "true" | "false"
  | comparison
  | "not" predicate
  | predicate "and" predicate
  | predicate "or" predicate
  | "(" predicate ")";
Кванторы
quantifier = ("forall" | "exists") "(" variableDef "|" predicate ")";
Имя переменной квантора уникально в области: requires — параметры; ensures — параметры+возвраты; invariant — параметры, возвраты, локальные.

Ссылки на формулы
formulaRef = identifier "(" [ expr {"," expr} ] ")";
Вывод типов локальных переменных
Тип локальной переменной без аннотации выводится из первого присваивания.
Контекст задаёт ожидания: арифметика/сравнения/индексы требуют int; length(x) и arrayAccess возвращают int; вызовы функций имеют объявленные типы.
Пример обессахаривания фиксирует типы массивов: a[i]=42; → a: int[], индекс — int.
Если тип не удаётся вывести или вывод противоречив — семантическая ошибка. Параметры и возвращаемые значения всегда аннотируются явно.




HW1. Лексер: регулярное выражение → ДКА → минимизация
Цели
Превратить набор регулярных выражений в ДКА и минимизировать его.
Подготовить таблицу переходов для будущего лексера проекта.
Собрать тесты на краевые случаи токенов.
Задание
Принять список регулярных выражений для токенов языка Funny (IDENT, INT, WS, COMMENT, OP/делимитеры/ключевые слова function/returns/...).
Построить НКА (Томпсон) → ДКА (subset construction) → минимизированный ДКА (Хопкрофт).
Сгенерировать таблицу переходов (формат на выбор: JSON/CSV/код).
Добавить «ловушку» для непокрытых символов.
Подготовить набор положительных и отрицательных тестов.
Требования к реализации
Язык реализации - любой, но воспроизводимый из CLI.
Поддержка позиций не обязательна (будет в HW2).
WS/COMMENT можно пометить как «skip», остальные токены — принимающие.
Алфавит входа: ASCII (фиксирован в спецификации языка); важно покрытие всех символов в тестах.
Вход/выход (минимальный сценарий)
Вход: файл с регулярными выражениями или вшитый список.
Выход: сериализованный ДКА (переходы, стартовое состояние, принимающие), список тестов и их статусы.
Тестирование
Обязательные сценарии: пустая строка; строки только из пробелов/табов/CRLF; 0, 00, 01 (отрицательный пример); идентификаторы с _; ключевые слова (function, returns, while, if, else, assert, assume, invariant, length); границы/операторы ()[]{},; + - * / == != <= >= < > =; комментарии //... до конца строки; выход за алфавит (non-ASCII) должен попадать в ловушку.
Проверка: прогон тестовых строк через построенный ДКА, сравнение ожидаемых токенов/ошибок.
Формат сдачи
Код + README с инструкцией запуска.
Отчёт (кратко): список регулярных выражений, размер ДКА до/после минимизации, ловушка.
Тесты: входные строки + ожидаемый результат.
Дополнительно: экспорт таблицы переходов/автомата так, чтобы её можно было подключить в лексер проекта (T0).
Критерии оценки (10 баллов)
Корректное построение и минимизация ДКА — 4 балла
Покрытие тестами, граничные случаи — 2 балла
Формат вывода/таблиц и воспроизводимость — 2 балла
Отчетность и структура — 2 балла
Связь с проектом
Белый ящик: код и тесты из HW1 должны переиспользоваться в лексере для контрольной точки T0.
Срок
Открытие на неделе 2 после L02 и P01; лексер закрепляется в P02 на неделе 3.
