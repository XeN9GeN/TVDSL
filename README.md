# HW1. Лексер Funny: NFA → DFA → минимизация

## 1) Структура проекта

```
src/main/java/
  NFA/
    NFAState.java      — состояние НКА (переходы по символам + ε-переходы, приоритет)
    NFMiniA.java       — пара состояний (start, finish) для фрагмента НКА Томпсона
    NFABuild.java      — конструкторы: fromChar, concatenate, or, cliniStar
  DFA/
    DFAState.java      — состояние ДКА (множество NFA-состояний, переходы, тип токена)
    DFABuild.java      — subset construction (ε-closure + move)
    MinimizeDFA.java   — минимизация (разбиение классов эквивалентности)
    DFAAutomaton.java  — финальный автомат/состояние ловушка/сериализация в JSON
    DFAInterpreter.java — прогон строки по ДКА
src/test/java/
  FunnyLexerTest.java  — JUnit 5 тесты
target/dfa_table.json  — экспортированная таблица переходов
```

## 2) Регулярные выражения токенов

| Токен | Регулярка | Тип |
|---|---|---|
| INT | `0 \| [1-9][0-9]*` | принимающий |
| WS | `[ \t\n\r]*` | skip |
| IDENT | `[A-Za-z_][A-Za-z0-9_]*` | принимающий |
| KEYWORDS | `function, returns, while, etc.` | принимающий |
| COMMENT | `//[^\n]*` | skip |
| Разделители | `(, ), [, ], {, }, ,, ;, :` | принимающий |
| Одиночные операторы | `+, -, *, /, =, <, >` | принимающий |
| Двухсимвольные операторы | `==, !=, <=, >=` | принимающий |

## 3) Приоритеты

Проблема: слово `if` подходит и под IDENT, и под ключевое слово. В одном и том же состоянии ДКА оказываются два финальных NFA-состояния с разными типами. Решение — поле `NFAState.priority`:

- IDENT → 0
- ключевые слова → 10

## 4) Ловушка

`DFAAutomaton` добавляет состояние:

- `id = 999`;
- `is_final_state = false`.

Для каждого символа алфавита `c` существует переход вида `999 --c--> 999`. У любого состояния, где не было перехода по `c`, добавляется переход в `999`.
