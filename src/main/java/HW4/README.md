# HW4: Промежуточное представление (IR), CFG и базовые оптимизации

Данный модуль реализует генерацию трехадресного кода (TAC), построение графа потока управления (CFG), базовые локальные оптимизации и распределение регистров (жадная раскраска графа) для компилятора языка Funny.

## 1. Формат промежуточного представления (IR)

IR генерируется в виде списка строк (трехадресный код). Каждая инструкция представляет собой простое действие с максимум тремя операндами.

**Поддерживаемые типы инструкций:**

**Математика и присваивание:**

```text
t1 = a + b
x = 5
t2 = -a
```

**Доступ к массивам:**

```text
t1 = a[0]
a[t1] = 5
```

**Вызовы функций:**

```text
t1 = call foo, a, b
```

**Метки базовых блоков:**

```text
L L1
```

**Безусловный переход:**

```text
goto L1
```

**Условный переход:**

```text
if a > b goto L1
```

## 2. Архитектура и структура

- **IRGeneration**: Обходит аннотированный AST (из HW3) и генерирует линейный список инструкций.
- **CFGBlocks**: Разбивает линейный код на Базовые Блоки (`Block`), определяя "лидеров" (метки, цели переходов) и выстраивая связи `Successors` (куда идем) и `Predecessors` (откуда пришли).
- **Optimizer**: Применяет локальные оптимизации к каждому базовому блоку.
- **LifeInterval**: Выполняет анализ живости переменных (Liveness Analysis).
- **GreedyGraph**: Строит граф конфликтов и выполняет жадную раскраску для распределения регистров.

## 3. Оптимизации и флаги

В классе `Optimizer` реализован метод `optimize(...)`. Оптимизации можно включать и отключать с помощью логических флагов:

- **foldConst (Constant Folding)**: Свёртка констант. Например, `t1 = 2 + 3` превращается в `t1 = 5`.
- **simpleAlg (Algebraic Simplification)**: Алгебраические упрощения. Например, `x * 1` → `x`, `y + 0` → `y`, `z * 0` → `0`.
- **DCE (Local Dead Code Elimination)**: Удаление мертвого кода. Реализовано в виде двухпроходного алгоритма (Mark & Sweep). Переменная считается мертвой, если она записывается, но никогда не читается в блоке. Возвращаемые переменные функции защищены от удаления.

Оптимизатор работает в цикле (`while(changed)`), достигая неподвижной точки: изменения, внесенные одной оптимизацией, позволяют сработать другим (например, после FoldConst переменная становится мертвой и удаляется DCE).

## 4. Пример работы (До и После)

**Исходный код на Funny:**

```funny
function main() returns r: int {
    dead1 = 10 * 5;
    x = 2 + 3;
    y = x * 1;
    r = y + 0;
}
```

**IR до оптимизаций:**

```text
t1 = 10 * 5
dead1 = t1
t2 = 2 + 3
x = t2
t3 = x * 1
y = t3
t4 = y + 0
r = t4
```

**IR после оптимизаций (все флаги = true):**

```text
t2 = 5
x = t2
t3 = x
y = t3
t4 = y
r = t4
```

**Примечание:** выражения dead1 удалены полностью вместе с временной переменной t1 благодаря DCE.

## Анализ живости и Граф конфликтов

**LifeInterval:** Вычисляет интервалы [start, end] для каждой переменной на основе первого и последнего упоминания.

**GreedyGraph:** Строит граф, где вершины — переменные, а ребра — пересечения их интервалов жизни (конфликты). Раскраска выполняется жадным алгоритмом с предварительной сортировкой по алгоритму Уэлша-Пауэлла (по убыванию степени вершины) для минимизации количества используемых регистров.
