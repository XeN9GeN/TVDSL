# HW5: Темпоральные спецификации и проверка моделей

## Описание модели
**Модель:** Ограниченная очередь.
**Инструментальная ветка:** Spin/Promela.
**Параметры:** Ёмкость `N=2`. Пусть очередь уже защищена мьютексом.

## Структура проекта
* `queue.pml` — исходный код модели на Promela.
* `/HW5/queue_right/results` — лог успешной проверки исправной модели для каждого из свойств.
* `/HW5/queue_buggy/results` — лог успешной проверки багованной модели для каждого из свойств.
* `README.md` — инструкция.
* `commands.txt` — команды запуска

## Спецификации (LTL)
В коде `queue.pml` заданы 5 свойств:
* **Безопасность (Safety):**
  * `S1`: `[] (count <= N)` (Нет переполнения)
  * `S2`: `[] (count >= 0)` (Нет некорректного опустошения)
  * `S3`: `[] (!err)` (Нет аварийного состояния)
* **Живость (Liveness):**
- `L1`: каждый принятый элемент в конечном итоге извлекается.В модели используются два идентификатора (`1` и `2`). Флаги `pending1` и
  `pending2` устанавливаются при помещении соответствующего элемента и сбрасываются только при его извлечении. Один идентификатор не может
  одновременно находиться в очереди более одного раза. Формула проверяет, что каждый установленный флаг `pending` в итоге сбрасывается.
- `L2`: `[] (count > 0 -> <> (count == 0))` — всякий раз, когда очередь
  непуста, она в итоге становится пустой.

## Допущения модели для L2
L2 не выводится из одной лишь справедливости процесса или флага `-f`. Справедливость процесса не гарантирует справедливый выбор между ветвями
одного процесса.

В этой модели опустошение обеспечивается отдельным ограничением поведения: когда `count` достигает `N`, устанавливается `draining=1`. Пока `draining=1`,
новые элементы не принимаются; выполняется не более одного отказа запроса при полной очереди, после чего ветвь отказа отключается флагом
`full_reject_done`. Извлечение остаётся разрешённым до `count==0`, после чего `draining` сбрасывается.

Таким образом, L2 проверяется при явно заданной политике: после заполнения очередь должна перейти в фазу дренирования и не может снова пополняться до
полного опустошения. Это допущение сильнее обычной семантики ограниченной очереди и не должно трактоваться как гарантия для произвольной реализации
очереди без такой политики.
