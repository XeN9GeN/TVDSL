Модель: ограниченная очередь

Инструментальная ветка: Spin/Promela (многопоточная)





\---Описание:

Есть очередь ёмкости N. Пользователь может:

&#x09;- положить элемент (enqueue), если очередь не заполнена.

&#x09;- забрать элемент (dequeue), если очередь не пуста.



Если очередь заполнена, enqueue блокируется/отвергается; если пуста — dequeue блокируется/отвергается. Потерь сообщений нет: каждый положенный элемент рано или поздно либо извлекается.





\---Состояния:



M = {S, S0, R, L}

S = {s0,s1,s2,s3}

S0 = {s0} - начальное



Переходы:

* s0 -> s1 - enq (0->1)
* s1 -> s2 - enq (1->2)
* s1 -> s0 - deq (1->0)
* s2 -> s1 - deq (2->1)
* s2 -> s2 - !enq (full)  отказ операции
* s0 -> s0 - !deq (empty) отказ операции



Состояние	count	Истинные атомы	Следующие состояния

s0		0	empty		s0, s1

s1		1	mid		s0, s2

s2		2	full		s1, s2

s3		—	error		s3



Трасса:

s0 → s1 → s2 → s1 → s0

count: 0→1→2→1→0





\---Переменные:

Имя		Значения

count		0...N

err		bool



Атомарные предикаты: 

* empty := count = 0
* mid := count = 1
* full := count = N
* error := err
* enq := переход
* deq := переход





\---Требования:

* Нет переполнения очереди; count <= N
* Буфер никогда не опустошается некорректно; count >= 0
* Каждый запрос будет рано или поздно принят и сделан/каждый принятый элемент рано или поздно извлечён или явно отвергнут





\---Допущения:

* *s3 недостижимо в исправной модели.*
* *Предполагаем, что очередь защищена мьютексом/другим примитивом синхронизации.*
* *Размер очереди N=2; Один потребитель, один производитель.*
