# Funny compiler (HW1–HW4)

Консольная программа принимает исходный код поддерживаемого подмножества языка Funny из UTF-8-файла, запускает реализованные этапы HW1–HW4 и сохраняет результаты анализа.

## Структура

- `Main.java` — точка входа: аргументы командной строки, чтение входного файла, вывод и сохранение результатов.
- `Compiler/FunnyCompiler.java` — координация этапов компиляции и сбор результатов.
- `DFA/FunnyAutomatonFactory.java` — построение и кеширование DFA для лексического анализатора.
- `NFA/` — построение недетерминированного конечного автомата.
- `DFA/` — детерминизация, минимизация и представление DFA.
- `lexer/` — лексический анализ: преобразование символов исходного текста в токены.
- `AST/` — синтаксический анализ, узлы AST и сериализация дерева в JSON.
- `HW3/` — семантический анализ: проверка типов, объявлений, имён и вызовов функций.
- `HW4/IRCode/` — генерация трёхадресного промежуточного кода (IR).
- `HW4/Blocks/` — построение графа потока управления (CFG).
- `HW4/Optimizations/` — свёртка констант, алгебраические упрощения и удаление мёртвого кода.
- `HW4/LifeInterval.java` — интервалы жизни переменных внутри базовых блоков.
- `HW4/GreedyGraph.java` — граф конфликтов переменных и жадная раскраска.
- `HW4/HW4Saver.java` — вспомогательное сохранение IR и CFG.
- `HW5/` — материалы HW5; в конвейер этой программы не входят.

## Конвейер компиляции

`Funny source → FunnyLexer → ParserFunny → AST → CheckAnalyzer → IRGeneration → CFGBlocks → Optimizer → LifeInterval → GreedyGraph`

DFA строится один раз при первом запуске компилятора в JVM и используется повторно. Парсер, семантический анализатор, генератор IR, CFG и остальные изменяемые компоненты создаются для каждой компиляции заново.

Оптимизатор изменяет базовые блоки на месте, поэтому программа строит два независимых CFG: исходный и оптимизируемый.

## Сборка и запуск

Требуются JDK 24 и Maven. Команды выполняются из корня репозитория.

Собрать проект:

```bash
mvn package
```

Создать файл, например `program.funny`:

```text
function main(a: int) returns r: int {
    x = a + 1;
    r = x;
}
```

Запустить все этапы с выводом в консоль:

```bash
java -cp target/classes Main program.funny --show=all
```

Общий формат команды:

```bash
java -cp target/classes Main <путь-к-файлу.funny> [--show=<режим>]
```

### Настройка вывода

Параметр `--show` определяет, какие результаты показывать в консоли:

- `all` — все результаты; используется по умолчанию.
- `tokens` — токены после лексического анализа.
- `ast` — AST в формате JSON.
- `ir` — промежуточный код.
- `cfg` — исходный CFG.
- `optimized` — CFG после оптимизации.
- `intervals` — интервалы жизни переменных.
- `graph` — конфликтный граф и цвета.
- `none` — не показывать промежуточные результаты.

Можно указать несколько этапов через запятую:

```bash
java -cp target/classes Main program.funny --show=tokens,ast,ir
```

Справка:

```bash
java -cp target/classes Main --help
```

Выбранный режим влияет только на вывод в консоль: результаты всех этапов сохраняются в относительный каталог `output/<имя-входного-файла>/`:

- `tokens.txt`
- `ast.json`
- `ir.txt`
- `cfg.txt`
- `optimized.txt`
- `intervals.txt`
- `graph.txt`

Ошибки чтения файла и ошибки лексического, синтаксического или семантического анализа выводятся в stderr. При ошибке программа завершается с ненулевым кодом.

## Ограничения

Поддерживается только то подмножество Funny, которое реализовано всеми этапами проекта. Наличие токена или AST-класса само по себе не означает поддержки конструкции конвейером. Например, кванторы и формулы не реализованы полностью; `uses` не разбирается грамматикой; предусловия, постусловия и инварианты не полностью отражаются в IR. Интервалы вычисляются в рамках отдельных базовых блоков, а жадная раскраска графа является учебной моделью и не выполняет полноценное распределение машинных регистров.
